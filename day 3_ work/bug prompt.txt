- Bug ID
- Requirement ID
- Test Case ID
- Bug Title
- Module
- Feature
- Environment
- Build/Version
- Browser
- Severity
- Priority
- Defect Type
- Preconditions
- Test Data
- Steps to Reproduce
- Expected Result
- Actual Result
- Error Message
- Evidence
- Status
- Confidence Level

Requirements:
- Generate multiple bug reports based on the identified issues.
- Use professional defect management terminology.
- Clearly separate Expected Result and Actual Result.
- Write detailed, reproducible Steps to Reproduce.
- Assign Severity based on business impact.
- Assign Priority based on release urgency.
- Distinguish application defects from test or environment issues.
- Do not assume missing information. If data is unavailable, use "Not Available".
- Do not include sensitive or real user information.
- Include a Confidence Level for each defect classification.
- Create the final output in a structured Excel workbook with proper formatting, headers, filters, and column widths.

The bug reports should be realistic, detailed, and suitable for project-level QA documentation and defect tracking.
